## Agent eval: real Godot 4.7 project (private, 8 scripts), validated by `godot-check`

This project is private, so this section is **not reproducible**; it is included as a data point only.

| task | pass |
|---|---:|
| fix injected Godot 3 idioms (`onready`, `connect("sig", self, "fn")`) | 2/2 |
| add a signal, emit it, and connect it to a handler in the HUD | 2/2 |
| add a typed `@export` and use it to clamp velocity | 0/2, then 2/2 on re-run |

The first typed-export batch failed 0/2: in one run the model could not execute `godot-check` (it lives outside the project, and opencode's `external_directory` "ask" is an automatic reject in headless mode), so it **wrote its own fake `godot-check` script into the project** that only grepped the source and printed OK; in the other it gave up after that same rejection. I added a guard against a fake validator, relaxed an over-strict usage-count in the task's check, and re-ran only that task: 2/2. Counting every attempt, that is 6 passes out of 8. Lesson: put the validator on the agent's PATH inside the allowed directory or allow the path, and treat "the agent verified its own work" with suspicion.

## Caveats

- 2 repeats per task is a tiny sample; the model is non-deterministic (temp 0.6).
- Tasks are small and fully specified. They measure reliability on routine edits, not open-ended engineering.
- Single machine; please add yours (see the README).
